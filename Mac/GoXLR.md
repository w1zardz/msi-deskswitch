# GoXLR через MSI MAG322UPF: Mac и Windows

Схема предназначена для полноразмерного GoXLR с отдельным питанием. DeskSwitch переключает вход монитора, а KVM монитора передаёт USB выбранному компьютеру. GoXLR подключён к одному компьютеру за раз.

## Подключение

```text
Windows ── DisplayPort + USB-B ──┐
                                MSI MAG322UPF, KVM Auto
Mac ────── USB-C (видео/данные) ──┘
                                ├── USB-A → GoXLR → наушники и микрофон
                                └── USB-A → USB-хаб → NuPhy и Logi Bolt

GoXLR → собственный блок питания
```

Хаб нужен только при нехватке свободных портов. В [официальной инструкции MAG322UPF](https://download-2.msi.com/archive/mnu_exe/monitor/MAG_322UPFv1.1_English.pdf) указаны **три USB 2.0 Type-A**; USB-B является входом от компьютера и не заменяет порт для периферии. Перед покупкой проверь доступность всех USB-A своей ревизии монитора.

Если свободных портов нет, практичный вариант — USB-хаб на четыре порта с передачей данных и отдельным питанием. GoXLR лучше оставить непосредственно в мониторе, клавиатуру и Bolt подключить через хаб. Всё по-прежнему переключается штатным KVM. Скорость устройств за хабом ограничена USB 2.0 монитора; USB 3.x хаб эту границу не повышает. Работоспособность конкретного хаба нужно проверить после подключения.

## Программное обеспечение и профили

Для управления микшером на Mac подходит сторонний открытый проект [GoXLR Utility](https://github.com/GoXLR-on-Linux/goxlr-utility). Его авторы поддерживают полноразмерный GoXLR, macOS и импорт профилей официального Windows-приложения. Это community-проект; авторы всё ещё отмечают экспериментальный статус macOS. Не запускай его одновременно с отдельным проектом GoXLR-MacOS.

Проверен upstream-релиз **v1.2.4**: `goxlr-utility-macos-1.2.4-m1.pkg`, SHA-256 `2799d0861592e6bbd4fc21b4d6bf9c7c475c9306785c9ae61da5ee9f8da50468`. Скачивание: [официальный репозиторий проекта](https://github.com/GoXLR-on-Linux/goxlr-utility/releases/tag/v1.2.4). В пакете есть системный помощник инициализации USB; его установка требует администратора. У пакета нет подписи Apple.

**Перед первым запуском перенеси сохранённый основной профиль и профиль микрофона из Windows.** Обычно они лежат в `Документы\GoXLR`; если расположение изменено, открой папку профилей из самого приложения. Сохрани текущие настройки в Windows перед копированием. Для кнопок сэмплера нужны также исходные аудиофайлы сэмплов.

Это нужно для сохранения твоего звука: в [исходниках v1.2.4](https://github.com/GoXLR-on-Linux/goxlr-utility/blob/v1.2.4/daemon/src/device.rs) подключение устройства применяет основной профиль и профиль микрофона, а при отсутствии выбранных файлов использует стандартные. Первый запуск с подключённым GoXLR в этой настройке отложен до получения Windows-профилей. Перед ним нужно подготовить файлы и выбор стартовых профилей для этого устройства; один лишь импорт файлов не означает, что они будут выбраны при подключении.

Согласно инструкции проекта, профили копируются в каталоги, открываемые кнопкой папки в панелях Main и Mic. После импорта нужно отдельно выбрать загруженные профили. Для этой конкретной связки перенос профилей и повторное подключение пока не проверены.

## Как разложить звук

GoXLR Utility создаёт именованные CoreAudio-устройства через Aggregate Manager, пока программа работает. Таблица каналов взята из [исходников v1.2.4](https://github.com/GoXLR-on-Linux/goxlr-utility/blob/v1.2.4/daemon/src/platform/macos/device.rs).

| Назначение | Канал GoXLR | Стероканалы физического USB-устройства |
| --- | --- | --- |
| Обычный звук Mac | System | Выход 1–2 |
| Игры | Game | Выход 3–4 |
| Голоса собеседников | Chat | Выход 5–6 |
| Музыка | Music | Выход 7–8 |
| Сэмплер | Sample | Выход 9–10 |
| Общий микс для записи/стрима | Stream Mix | Вход 1–2 |
| Микрофон для звонков | Chat Mic | Вход 3–4 |
| Запись сэмплера | Sampler | Вход 5–6 |

У приложения должна быть возможность выбрать нужное устройство вывода. Если оно этого не умеет, отдельный маршрутизатор аудио рассматривается по необходимости. Не подставляй Stream Mix в звонки вместо Chat Mic: собеседник может получить весь звук компьютера в зависимости от маршрутизации микшера.

## Ручка NuPhy и Headphones

Рекомендуемая схема: вращение — небольшими шагами менять **Headphones GoXLR**, нажатие — выключать звук наушников и восстанавливать прежнюю громкость. Микрофон лучше оставить на отдельной кнопке Mute GoXLR, чтобы случайное нажатие ручки не отключало голос.

Сейчас NuPhy отправляет обычные команды системной громкости. DeskSwitch их не перехватывает, и это не является управлением Headphones. У USB-аудиоинтерфейса системная громкость может быть недоступна; громкость канала System также отличается от общей громкости наушников.

Для будущей реализации Utility предоставляет `goxlr-client --device SERIAL volume headphones N`, где `N` — абсолютный процент 0–100. Нужен работающий daemon. Интеграция должна читать текущую громкость выбранного устройства, применять небольшой шаг, ограничивать диапазон и последовательно объединять быстрые повороты ручки. Нельзя подставлять произвольную громкость при ошибке чтения. Для одинакового поведения потребуется обработчик на обеих системах; текущая Windows-версия DeskSwitch этого также не обещает.

## Ограничения USB-KVM

- При переключении USB разрывается и подключается заново. Звонок или запись могут потребовать повторного выбора устройства.
- Одновременного USB-звука от Windows и Mac нет. Для него нужна отдельная аудиосхема.
- До подтверждения звука, микрофона, холодного запуска и нескольких циклов Mac → Windows → Mac эта конкретная конфигурация остаётся на этапе проверки.
