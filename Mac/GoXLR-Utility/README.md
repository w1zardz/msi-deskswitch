# GoXLR Utility: обнаружение USB-аудио в macOS Tahoe

Небольшая локальная поправка к официальной [GoXLR Utility v1.2.4](https://github.com/GoXLR-on-Linux/goxlr-utility/tree/v1.2.4), commit `0c093b4c9bfb59d3426357c008760ad6620f97ae`.

В новой macOS физический GoXLR может работать через `usbaudiod`, не публикуя старые службы `IOAudioEngine`. Utility видит USB-микшер и управляет его настройками, но прежнее обнаружение аудиоустройства возвращает пустой список. Поэтому не появляются отдельные устройства System, Chat Mic и остальные каналы.

`patches/tahoe-coreaudio.patch` сохраняет прежний поиск по USB VID/PID. Если он ничего не нашёл, патч читает список CoreAudio. Принимаются только физические устройства с транспортом USB и подтверждённой парой `TC-Helicon` / `GoXLR` или `GoXLR Mini`, либо соответствующим префиксом системного USB UID. Агрегаты и похожие названия исключаются. UID конкретного пользователя не зашит. Патч не меняет маршрутизацию, профили, громкость или микрофон; найденное устройство передаётся существующему механизму создания агрегатов Utility.

## Сборка Apple Silicon

Нужны Command Line Tools for Xcode, Rust с поддержкой edition 2024 и target `aarch64-apple-darwin`. Скрипт использует зафиксированный Cargo.lock и все штатные возможности daemon, включая TTS.

```sh
git clone --branch v1.2.4 https://github.com/GoXLR-on-Linux/goxlr-utility.git /tmp/goxlr-upstream
bash Mac/GoXLR-Utility/build-tahoe.sh /tmp/goxlr-upstream /tmp/goxlr-tahoe-build
```

Каталог результата должен быть новым. Скрипт извлекает чистую копию указанного upstream-коммита, применяет патч без fuzz, собирает daemon и запускает тесты классификации. Исходный checkout остаётся нетронутым. Необязательная переменная `GOXLR_CARGO_TARGET_DIR` позволяет использовать существующий абсолютный путь к кэшу Cargo.

Результат — `artifact/goxlr-daemon` с лицензиями; журналы `build.log` и `test.log` остаются в каталоге сборки. Скрипт ничего не устанавливает, не запускает daemon и не меняет пользовательские профили.

Отдельная проверка обнаружения подключённого GoXLR только читает свойства устройств:

```sh
cd /tmp/goxlr-tahoe-build/source
CARGO_TARGET_DIR=/tmp/goxlr-tahoe-build/target cargo test --locked --release --all-features \
  -p goxlr-daemon --target aarch64-apple-darwin \
  discovers_connected_goxlr_read_only -- --ignored --nocapture
```

## Установка и лицензия

Бинарник предназначен для отдельной проверенной замены daemon внутри уже установленной Utility v1.2.4. Перед заменой нужно штатно завершить Utility, сохранить прежний бинарник и проверить подпись пакета после изменения. Сборка сама этих действий не выполняет. Настройки и личные профили хранятся в стандартном каталоге Utility вне репозитория.

Upstream распространяется по MIT; копии `LICENSE` и `LICENSE-3RD-PARTY` находятся рядом. Поправка распространяется на тех же условиях. Это локальная сборка с поправкой, а не официальный релиз GoXLR Utility.

## Проверка на устройстве

12.09.2026 на Mac с полноразмерным GoXLR через MSI USB KVM: создано восемь именованных аудиоустройств, System выбран выходом, Chat Mic — входом. Владелец подтвердил слышимый звук и изменение громкости наушников крутилкой NuPhy. После одного цикла отключения/возврата USB с этой сборкой восстановились устройство, выбранные профили и аудиоустройства по умолчанию. Проверка сна и записи микрофона в приложениях ещё нужна.
